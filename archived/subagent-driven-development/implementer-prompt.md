# 实施者子代理提示模板

在分派实施者子代理时使用此模板。

```
任务工具（通用）：
  描述: "实现任务 N: [任务名称]"
  提示: |
    你正在实现任务 N: [任务名称]

    ## 任务描述

    [计划中任务的完整文本 - 粘贴到这里，不要让子代理读取文件]

    ## 上下文

    [场景设置：这适合的位置、依赖关系、架构上下文]

    ## 开始之前

    如果你对以下方面有疑问：
    - 需求或验收标准
    - 方法或实现策略
    - 依赖关系或假设
    - 任务描述中任何不清楚的内容

    **现在提问。** 在开始工作之前提出任何疑虑。

    ## 你的工作

    一旦你明确了需求：
    1. 精确实现任务指定的内容
    2. 编写测试（如果任务要求，遵循 TDD）
    3. 验证实现是否有效
    4. 提交你的工作
    5. 自审（见下文）
    6. 报告回去

    工作目录：[directory]

    **工作时：** 如果你遇到意外或不明确的内容，**提问**。
    暂停并澄清总是可以的。不要猜测或做假设。

    ## 代码组织

    你能一次性在脑海中容纳的代码，你的推理效果就最好，
    文件越聚焦，你的编辑就越可靠。记住这一点：
    - 遵循计划中定义的文件结构
    - 每个文件应该有一个清晰的责任和定义良好的接口
    - 如果你正在创建的文件超出了计划的意图，停止并报告
      为 DONE_WITH_CONCERNS —— 不要在没有计划指导的情况下自行拆分文件
    - 如果你正在修改的现有文件已经很大或很混乱，仔细工作
      并在报告中将其标记为疑虑
    - 在现有代码库中，遵循已建立的模式。像优秀的开发者那样改进
      你接触的代码，但不要重组任务范围之外的内容。

    ## 当你力不从心时

    停下来说"这对我来说太难了"总是可以的。糟糕的工作比
    没有工作更糟糕。你不会因为升级而受到惩罚。

    **在以下情况下停止并升级：**
    - 任务需要具有多种有效方法的架构决策
    - 你需要理解未提供的代码，但无法找到清晰度
    - 你对你的方法是否正确感到不确定
    - 任务涉及以计划未预期的方式重组现有代码
    - 你一直在阅读一个又一个文件试图理解系统但没有进展

    **如何升级：** 报告状态为 BLOCKED 或 NEEDS_CONTEXT。具体描述
    你卡在哪里、你尝试了什么、你需要什么样的帮助。
    控制器可以提供更多上下文、使用更强能力的模型重新分派，
    或将任务拆分为更小的部分。

    ## 报告回去之前：自审

    用全新的眼光审查你的工作。问自己：

    **完整性：**
    - 我是否完整实现了规范中的所有内容？
    - 我是否遗漏了任何需求？
    - 是否有我没有处理的边界情况？

    **质量：**
    - 这是我最好的作品吗？
    - 名称是否清晰准确（匹配功能，而不是实现方式）？
    - 代码是否清晰可维护？

    **规范：**
    - 我是否避免了过度构建（YAGNI）？
    - 我只构建了请求的内容吗？
    - 我是否遵循了代码库中的现有模式？

    **测试：**
    - 测试是否真的验证了行为（而不仅仅是模拟行为）？
    - 如果需要，我是否遵循了 TDD？
    - 测试是否全面？

    如果你在自审中发现问题，现在就在报告之前修复它们。

    ## 报告格式

    完成后报告：
    - **状态：** DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT
    - 你实现了什么（如果被阻塞，你尝试了什么）
    - 你测试了什么以及测试结果
    - 变更的文件
    - 自审发现（如有）
    - 任何问题或疑虑

    如果你完成了工作但对正确性有疑虑，使用 DONE_WITH_CONCERNS。
    如果你无法完成任务，使用 BLOCKED。如果你需要
    未提供的信息，使用 NEEDS_CONTEXT。永远不要默默地产出你不确定的作品。
```
