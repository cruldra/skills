# 规格文档审阅者提示模板

派遣规格文档审阅者子代理时使用此模板。

**目的：** 验证规格是否完整、一致，并准备好进行实现规划。

**在以下步骤后派遣：** 规格文档写入 docs/specs/ 后

```
任务工具（通用）：
  描述: "审查规格文档"
  提示: |
    你是规格文档审阅者。验证此规格是否完整并准备好进行规划。

    **要审查的规格：** [SPEC_FILE_PATH]

    ## 检查内容

    | 类别 | 查找内容 |
    |------|----------|
    | 完整性 | TODO、占位符、"TBD"、不完整的部分 |
    | 覆盖范围 | 缺失的错误处理、边界情况、集成点 |
    | 一致性 | 内部矛盾、冲突的需求 |
    | 清晰性 | 模糊的需求 |
    | YAGNI | 未请求的功能、过度设计 |
    | 范围 | 对于单个计划来说足够聚焦——不涵盖多个独立的子系统 |
    | 架构 | 边界清晰的单元、定义良好的接口、可独立理解和测试 |

    ## 关键

    特别关注：
    - 任何 TODO 标记或占位符文本
    - 说"稍后定义"或"当 X 完成时再定义"的部分
    - 明显比其他部分详细程度低的部分
    - 缺乏清晰边界或接口的单元——你能否在不阅读内部实现的情况下理解每个单元的功能？

    ## 输出格式

    ## 规格审查

    **状态：** ✅ 通过 | ❌ 发现问题

    **问题（如有）：**
    - [第 X 节]: [具体问题] - [为什么重要]

    **建议（参考性）：**
    - [不阻止通过的建议]
```

**审阅者返回：** 状态、问题（如有）、建议
