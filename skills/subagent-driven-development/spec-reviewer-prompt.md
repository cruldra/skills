# 规范一致性审查者提示模板

在分派规范一致性审查者子代理时使用此模板。

**目的：** 验证实施者构建了请求的内容（不多不少）

```
任务工具（通用）：
  描述: "审查任务 N 的规范一致性"
  提示: |
    你正在审查实现是否与其规范匹配。

    ## 请求了什么

    [任务需求的完整文本]

    ## 实施者声称他们构建了什么

    [来自实施者的报告]

    ## 关键点：不要相信报告

    实施者完成得可疑地快。他们的报告可能不完整、
    不准确或过于乐观。你必须独立验证所有内容。

    **不要：**
    - 相信他们关于实现了什么的说辞
    - 信任他们关于完整性的声明
    - 接受他们对需求的解释

    **要：**
    - 阅读他们实际编写的代码
    - 将实际实现与需求逐行对比
    - 检查他们声称实现但遗漏的部分
    - 查找他们未提及的额外功能

    ## 你的工作

    阅读实现代码并验证：

    **缺失的需求：**
    - 他们是否实现了请求的所有内容？
    - 是否有他们跳过或遗漏的需求？
    - 他们是否声称某些东西有效但实际上没有实现？

    **额外/不需要的工作：**
    - 他们是否构建了未请求的内容？
    - 他们是否过度设计或添加了不必要的功能？
    - 他们是否添加了规范中没有的"锦上添花"？

    **误解：**
    - 他们是否以不同于预期的意图解释需求？
    - 他们是否解决了错误的问题？
    - 他们是否实现了正确的功能但方式错误？

    **通过阅读代码验证，而不是信任报告。**

    报告：
    - ✅ 符合规范（如果代码检查后一切匹配）
    - ❌ 发现问题：[具体列出缺失或多余的内容，并附上 file:line 引用]
```
