# Adapt External TSX Reference

## 概述

本 Skill 用于处理“用户贴来一段外部 TSX 代码让你参考实现”的场景。

核心原则：默认把外部代码视为视觉、结构、交互参考，而不是实现层面的直接模板。实现时必须先适配当前项目技术栈，再落代码。

## 指令

1. 先判断用户要你参考的是哪一层：布局、交互、文案、状态流转，还是完整实现。
2. 默认保留参考代码的页面结构、信息层级和交互意图，不直接照搬依赖、组件库、样式系统和状态管理方案。
3. 实现前先检查当前项目已有方案，优先复用现有技术栈：
   - UI 组件库
   - 图标库
   - 路由方案
   - 表单方案
   - 状态管理
   - 样式系统
   - 主题机制
4. 如果参考代码使用了项目中不存在的依赖，默认不要新增；先换成项目现有能力。
5. 只有在用户明确要求，或当前项目确实没有等价方案时，才引入新依赖。
6. 参考代码中的颜色、暗黑模式、原子类、图标、动画等实现细节，必须先适配当前项目约束，不能直接复制。
7. 如果用户只说“参考这个实现”，优先理解为：参考视觉布局和交互，不代表接受其底层实现方式。
8. 如果参考代码与当前项目存在多套可选实现风格，先给出推荐方案；只有差异会明显影响结果时再向用户澄清。

## 默认适配规则

- 外部 `Tailwind` / `UnoCSS` 类名：默认不照搬，先改成当前项目认可的样式方案。
- 外部 UI 库组件：默认替换成当前项目已有组件库。
- 外部图标库：默认替换成当前项目已有图标库。
- 外部表单库：默认替换成当前项目现有表单方案。
- 外部状态管理：默认替换成当前项目现有状态方案。
- 外部主题判断：默认接入当前项目主题系统，不自建一套 `dark` / `light` 机制。
- 外部假数据和交互流程：可以参考，但命名、结构、注释要符合当前项目代码风格。

## 不要做的事

- 不要把“参考布局”误解成“照搬实现”。
- 不要擅自新增新的组件库、图标库、状态库、样式库。
- 不要复制与当前项目冲突的主题逻辑。
- 不要把参考代码里的技术债一并带进当前项目。

## 输出预期

当用户贴来外部 TSX 代码时，最终产物应满足：

- 页面结构和交互接近参考稿
- 代码实现符合当前项目技术栈
- 依赖增量最小
- 样式、图标、主题、状态管理与现有项目一致

## 使用要点

- “参考”优先指向产品层，而不是实现层。
- 先适配，再实现。
- 如果项目里已有对应方案，优先遵循现有方案，而不是外部代码。
- 如果用户明确说“就按这套库写”，再放宽适配约束。
